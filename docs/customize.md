# Форматы настройки собственной копии

Этот справочник нужен для адаптации исходников. Обычные действия родителей описаны в [памятке](family-guide.md). В приглашённой семье настройки сохраняются мастером и кабинетом, а для APK выдаются готовым пакетом — вручную править серверные файлы не требуется.

## 1. Профили и время

`config/family.json` содержит `profiles` (1–6 уникальных имён), `utcOffsetMinutes` и общую серию `goal`. Порядок профилей должен совпадать с меню каталога. После изменения исходной конфигурации выполните `python3 scripts/configure.py`: он обновляет `web/family-config.js`.

Смещение времени фиксировано; переход на летнее время не автоматический. После начала работы не переставляйте профили: индексы связаны с историей. В зарегистрированной семье активные настройки берутся из базы, а не из начального JSON; изменения имён/времени выполняются через обслуживание владельцем сервера.

Нейтральные изображения — `web/avatar-1.png`..`avatar-3.png`. Свои портреты храните в частной копии. Пакет из кабинета уже содержит нужные `avatar-*.png`, включая дополнительные профили.

## 2. Начальный каталог

`sync/catalog.json` заполняет новую базу при первом запуске. Формат: список `[день_вступления, меню_по_порядку_профилей]`. День — целое число дней от 1970-01-01, версии расположены по возрастанию. Правка этого файла не переписывает каталог работающей базы.

| Поле меню | Формат строки | Назначение |
| --- | --- | --- |
| `morning` | `["id", "Название"]` | Утренний блок |
| `afternoon` | `["id", "Название"]` | Дневные дела |
| `rewards` | `["id", "Название", ставка]` | Однократные супердела |
| `repeatables` | `["id", "Название", ставка]` | Несколько выполнений в день |

Сохраняйте уже использованные идентификаторы. Пять обязательных утренних ID — `bed`, `teeth`, `dress`, `breakfast`, `car`. Переименование подписи сохраняет действие; изменение состава минимума требует согласованных правок `sync/family.py`, `web/rules.js` и каталога. Постоянные и разовые дела после запуска добавляются через кабинет.

## 3. Цели

Общая серия `goal` задаёт `title`, `reward`, `points`, `days` и числовой `allowedSkips`. Для старых конфигураций поддерживается `allowOneSkip`.

Личные цели — необязательный `childGoals`: массив списков целей в порядке профилей. Пример одной цели внутри списка ребёнка:

```json
{
  "id": "0123456789abcdef0123456789abcdef",
  "kind": "weekly",
  "title": "Семейная прогулка",
  "reward": "Выбрать парк",
  "points": 7,
  "days": 3,
  "allowedSkips": 1,
  "durationDays": 7
}
```

`kind`: `weekly`, `monthly` или `individual`; `days` — шаги до результата, `points` — очки за шаг. Сервер назначает `startedAt` новым целям. Для `individual` задаётся `durationDays`; у остальных типов период определяется типом, месячный — календарным месяцем от даты старта. Полные диапазоны и проверку формата задаёт `sync/configuration.py`.

Правила переноса, пропусков и изменения действующей цели описаны один раз в [пользовательской памятке](family-guide.md#7-настройте-цели). Цели после регистрации сохраняются в базе и приходят клиентам 1.3+ при синхронизации. Новая цель не требует новой сборки APK; старый клиент сначала обновите с прежней подписью.
