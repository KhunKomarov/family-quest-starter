# Существующий HTTP API родительского кабинета

Справочник для агента с разрешённым HTTP-доступом. Для стандартной установки и управления через браузер этот раздел читать не требуется. [Основной маршрут](agent-guide.md).

Для агента с разрешённым HTTP-доступом интерфейс использует `GET /parent/api/state`, `GET /parent/api/settings`, `POST /parent/api/action`, `POST /parent/api/settings` и `GET /parent/api/connection`. Авторизация — родительская сессия после `POST /parent/api/login` с JSON `{"token":"ШЕСТИЗНАЧНЫЙ_КОД"}`. POST требует `Origin`, точно равный HTTPS-origin данной семьи; запросы несут её session cookie. Самостоятельно обходить вход или убирать проверку Origin нельзя. Токен детского устройства не даёт родительские права.

Для добавления постоянного дела `action` равен `catalog-add`; передаются `id` (новый 32-символьный hex для одной операции), `day` из актуального `state.today`, `section` (`afternoon`, `rewards`, `repeatables`), `title`, `children` (индексы из текущего списка профилей), а для последних двух категорий — `rate`. Для повтора запроса используйте тот же `id`. Для целей сначала считайте настройки и `revision`; отправляйте сохранённый `expected` и полный актуальный набор целей, сохраняя чужие идентификаторы и поля. Конфликт 409 требует перечитать состояние и разобраться в отличии, а не перезаписывать изменения другого родителя.

Предпочитайте готовые формы, если нет необходимости писать HTTP-клиент. Не выводите session cookie или код в историю команд. После любой записи проверьте ответ и состояние. Сетевой таймаут не доказывает, что запись не произошла: сначала проверьте журнал или повторите запрос с тем же идентификатором. Не используйте SSH/root для обычных задач семьи.
