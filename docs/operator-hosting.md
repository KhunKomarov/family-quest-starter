# Выдача приглашений и обслуживание семей

Эти команды выполняет владелец Ubuntu/Nginx-сервера. Друзья открывают личную ссылку и сами проходят регистрацию. Они не получают SSH-доступ, пароль root или доступ к управлению хостингом. Скрипт не меняет домашнюю службу `family-quest`, её базу или Nginx-vhost.

## Подготовка хоста

Нужны Python 3.9+, systemd, Nginx, Certbot с уже настроенным ACME-аккаунтом, порты 80/443 и DNS имён на IP сервера. Для обработки фотографий установите `sudo apt install python3-pil`; для тестов на другом компьютере нужен Pillow. Разместите проверенную копию проекта в `/opt/fq-hosted-template` с доступом только для администратора. Личные данные, `.local` и рабочая база в шаблон не входят.

```sh
sudo python3 /opt/fq-hosted-template/scripts/host-family.py init-host \
  --base-domain families.example.org
```

Это создаёт ограничения ресурсов и ежедневный таймер резервного копирования. Уже настроенный хост повторно инициализировать нельзя. В `/etc/fq-hosted/host.json` хранятся базовый домен и предел пилота. Для служебных имён можно указать `203.0.113.10.sslip.io`, заменив IP на свой.

## Новое личное приглашение

```sh
sudo python3 /opt/fq-hosted-template/scripts/host-family.py create \
  --slug guest-02 --certbot /path/to/certbot \
  --invite-output /root/private-delivery/guest-02-invite.txt
```

Создаётся отдельный пустой экземпляр со своим сертификатом. Ссылка сохраняется в закрытом файле 0600 и не печатается в журнале. Передайте только её нужной семье по личному каналу. По умолчанию она действует 7 дней; `--invite-days` позволяет выбрать 1–30 дней. Публичная ссылка на GitHub сама по себе не даёт приглашение.

Для уже созданного, но ещё пустого гостевого экземпляра:

```sh
sudo python3 /opt/fq-hosted-template/scripts/host-family.py invite \
  --slug guest-01 --days 7 --output /root/private-delivery/guest-01-invite.txt
```

Команда обновляет исходники и proxy только выбранного пустого экземпляра, делает резервную копию и перезапускает его службу. Для новой версии на сервере сначала обновите проверенный `/opt/fq-hosted-template`. Текущий домашний трекер не затрагивается. Повторная выдача приглашения делает предыдущую ссылку недействительной. Создать приглашение поверх зарегистрированной семьи или журнала с выполненными делами нельзя.

```sh
sudo python3 /opt/fq-hosted-template/scripts/host-family.py revoke-invite --slug guest-01
```

Отзыв запрещает незавершённую регистрацию, не удаляя журнал. Завершённую семью он не отключает.

## Обновление зарегистрированной семьи

После проверки новой версии в `/opt/fq-hosted-template`:

```sh
sudo python3 /opt/fq-hosted-template/scripts/host-family.py update --slug guest-01 --source /opt/fq-hosted-template
```

Команда делает резервную копию, заменяет код и перезапускает только выбранную семью. Журнал, родительские коды, фото и токены сохраняются; приглашение не перевыпускается. Флаг `--refresh-default-labels` меняет с сегодняшнего дня только точное прежнее стандартное название мытья на «Принять душ», сохраняя пользовательские названия и прошлую историю. Сначала проверьте обновление на отдельной тестовой семье.

Родительская страница «Цели детей» работает после обновления сервера. Для личных целей и повторяемых дел на ранее установленных детских экранах потребуется один раз обновить APK до 1.3 или новее с прежней подписью и доступами. Дальше эти изменения приходят при синхронизации.

## Что происходит при регистрации

Родители вводят 1–6 имён детей, фотографии или выбор аватаров, местное время, индивидуальные списки дел, цель и один или два шестизначных кода. Приложение проверяет данные и повторно сверяет приглашение в транзакции SQLite. Настройки, коды, фотографии, каталог и факт использования ссылки сохраняются вместе. Две одновременные отправки не создают две семьи и не перезаписывают уже сохранённую.

До регистрации обычные родительские и детские API закрыты. После регистрации исходный токен приглашения не даёт читать сведения семьи. Срок и SHA-256 токена лежат в приватной базе; сам токен присутствует только в выдаваемом файле ссылки и её URL-фрагменте. Nginx не пишет access-log, в HTTP-журнал приложения не попадают тела запросов или коды.

Фотографии проверяются Pillow, приводятся к PNG 256×256 без исходных метаданных. SVG, произвольные файлы и слишком большие изображения отклоняются. Запрос регистрации ограничен 2,8 МБ в Python и 3 МБ в Nginx. База хранит только уменьшенные портреты. У родителя есть авторизованный маршрут `/parent/avatar/INDEX.png` и скачивание `/parent/api/connection`; чужие сессии туда не подходят.

В авторизованном кабинете родители или их помощник с управлением браузером скачивают архив через «Подключить экран». В нём актуальные имена, каталог, фотографии и токены устройств; родительские коды в веб-архив не входят. Сборка и установка APK выполняются на компьютере семьи с помощью её агента. Ничего передавать через администратора для регистрации не требуется.

## Изоляция и каталоги

| Данные | Путь |
| --- | --- |
| Копия приложения | `/opt/fq-hosted/SLUG` |
| Начальные доступы устройств и метаданные | `/etc/fq-hosted/SLUG` |
| База, включая настройки и фотографии регистрации | `/var/lib/fq-hosted/SLUG/journal.sqlite3` |
| Резервные копии | `/var/backups/fq-hosted/SLUG` |
| Служба и пользователь | `fq-hosted-SLUG.service`, `fq-SLUG` |

У каждой семьи свой HTTPS-хост. Приватные каталоги закрыты от соседних Linux-пользователей. Служба может писать только в свой каталог данных. Cookie использует `__Host-`, Secure, Path=/ и отсутствие Domain. Токены устройств и родительские сессии одной семьи не работают в другой.

Пилот ограничен четырьмя гостевыми семьями плюс домашний экземпляр. На гостевую службу: MemoryHigh 40 МиБ, MemoryMax 64 МиБ, CPUQuota 25%, TasksMax 32. На всех гостей вместе: 128/192 МиБ и 50% CPU. Это заданный бюджет ресурсов, а не доказанная предельная вместимость. Следите за `free -m`, `df -h /`, временем ответа и `systemctl show fq-hosted.slice -p MemoryCurrent -p CPUUsageNSec` до увеличения лимита.

## Обслуживание и резервные копии

```sh
sudo python3 /opt/fq-hosted-template/scripts/host-family.py status
sudo python3 /opt/fq-hosted-template/scripts/host-family.py backup --all
sudo systemctl status fq-hosted-backup.timer
```

Копии SQLite делаются через Backup API с проверкой целостности. Регистрационные настройки и фотографии входят в базу. Архив дополнительно включает актуальную конфигурацию и каталог; хранится в закрытом каталоге root. Таймер работает ежедневно в 03:15 UTC с задержкой до 15 минут. Автоматического удаления нет: контролируйте диск и переносите нужные архивы в согласованное закрытое хранилище. Локальная копия не заменяет внешний бэкап.

Для изменения имён или времени после регистрации администратор может применить `configure --slug SLUG --config PRIVATE_JSON`. Команда делает резервную копию и обновляет настройки только этой семьи. В зарегистрированной семье число и порядок профилей не меняйте. Смена времени и параметров цели влияет на историю; согласуйте её с семьёй. Личные цели и общую серию родители меняют через «Цели детей». После изменения имён или времени следует заново скачать настройки и пересобрать детские APK. Дела дальше меняются в родительской панели, не заменой стартового JSON.

Экспорт через CLI `export --slug SLUG --output PRIVATE_ZIP` остаётся служебным способом: этот архив может содержать родительские коды, поэтому не публикуйте его. Обычным семьям нужен только их веб-кабинет.

Для восстановления остановите только нужную службу, сохраните её текущие файлы, восстановите проверенную базу и права владельца, запустите её и проверьте данные с родителем. Используйте архив именно этой семьи. Конфигурация регистрации берётся из базы при старте, а не из исходного демонстрационного `config/family.json`.

Проверьте действующий `certbot renew` и deploy-hook с перезагрузкой Nginx. Тестовые отключённые экземпляры не должны оставаться на автоматическом продлении, если их HTTP-маршруты уже сняты. [Certbot webroot](https://eff-certbot.readthedocs.io/en/stable/using.html#webroot) · [Ограничения systemd](https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html).

Для приостановки семьи отключите только её службу и ссылку Nginx, проверьте `nginx -t`, перезагрузите proxy и сохраните файлы. Пометьте `enabled: false` в её `instance.json`. Удаление данных — отдельное согласованное действие.
