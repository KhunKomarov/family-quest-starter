# Несколько семей на одном сервере: инструкция владельцу

Эти команды выполняет владелец Ubuntu/Nginx-сервера, не друзья и не их агент. Семья получает только свой закрытый ZIP подключения. Скрипт не меняет службу `family-quest`, её Nginx-конфигурацию или домашнюю базу.

## Подготовка хоста

Нужны Python 3.9+, systemd, Nginx, работающий Certbot с уже настроенным ACME-аккаунтом, порты 80/443 и DNS имён на IP сервера. Разместите проверенную копию репозитория в `/opt/fq-hosted-template` с доступом только для администратора. `.local`, личные данные и рабочая база в неё не входят.

```sh
sudo python3 /opt/fq-hosted-template/scripts/host-family.py init-host \
  --base-domain families.example.org
```

Это создаёт лимиты Nginx, общую группу ресурсов `fq-hosted.slice` и ежедневный таймер резервного копирования. Существующие семейные службы не перезапускаются. При уже готовом хосте повторный `init-host` запрещён, чтобы не затереть настройки. `baseDomain` хранится в закрытом `/etc/fq-hosted/host.json`. Для временных адресов вместо своего домена можно указать `203.0.113.10.sslip.io`, заменив IP на адрес своего сервера. DNS должен уже разрешаться на него.

## Создание семьи по приглашению

Получите настройки семьи по личному каналу. Изображения детей можно оставить на компьютере семьи. Создайте экземпляр с нейтральным идентификатором, без фамилий в публичном имени:

```sh
sudo python3 /opt/fq-hosted-template/scripts/host-family.py create \
  --slug guest-01 --config /root/intake/guest-01/family.json \
  --catalog /root/intake/guest-01/catalog.json \
  --device tv:tv --device car:car --device tablet:touch \
  --certbot /path/to/certbot
sudo python3 /opt/fq-hosted-template/scripts/host-family.py export \
  --slug guest-01 --output /root/private-delivery/guest-01.zip
```

`--catalog` можно опустить для стартового набора примера. `--hostname` задаёт свой отдельный адрес вместо `SLUG.BASE_DOMAIN`. Локальный порт выбирается автоматически из 8801–8899. Скрипт откажется перезаписывать существующую семью, повторять имя хоста, занимать используемый порт или создавать экземпляр при недостатке доступной памяти. При сбое настройки публичный маршрут выключается, а частные файлы сохраняются для разбора. Повторять команду поверх них нельзя: сначала разберите причину.

После создания проверьте HTTPS, оба родительских входа и `/v2/sync` с токеном именно этой семьи. Проверьте, что чужие коды, сессии и токены отклоняются, а задания одной семьи отсутствуют у другой. Только после этого передайте ZIP этой семье через согласованный личный канал. Не добавляйте его в Releases, Issues или публичные чаты.

## Каталоги и ограничения

| Данные | Путь |
| --- | --- |
| Отдельная копия приложения и настроек | `/opt/fq-hosted/SLUG` |
| Родительские коды, устройства и метаданные | `/etc/fq-hosted/SLUG` |
| Журнал SQLite | `/var/lib/fq-hosted/SLUG/journal.sqlite3` |
| Резервные копии | `/var/backups/fq-hosted/SLUG` |
| Служба | `fq-hosted-SLUG.service`, пользователь `fq-SLUG` |

Каталоги приложения и кодов доступны root и группе только этой службы; база — только её пользователю. Служба не может изменять исходники или читать соседние закрытые каталоги. Родительский cookie использует префикс `__Host-`, HTTPS и отсутствие Domain, поэтому соседний семейный хост не может подставить его на весь домен. [Ограничения cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie#cookie_prefixes).

По умолчанию разрешены четыре гостевые семьи плюс существующий домашний экземпляр. Это предел пилота, не результат нагрузочного теста. На гостевую службу установлены MemoryHigh 40 МиБ, MemoryMax 64 МиБ, CPUQuota 25%, TasksMax 32. Все гости вместе ограничены MemoryHigh 128 МиБ, MemoryMax 192 МиБ и CPUQuota 50%. [Ресурсные ограничения systemd](https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html). Отклонённый по лимиту запрос клиент повторяет; превышение памяти может перезапустить службу, журнал остаётся в SQLite.

Следите за `free -m`, `df -h /`, `systemctl show fq-hosted.slice -p MemoryCurrent -p CPUUsageNSec` и временем ответа при одновременной работе экранов. Повышайте лимит семей в `host.json` только после проверки нагрузки и запаса ресурсов.

## Настройки, резервные копии и восстановление

```sh
sudo python3 /opt/fq-hosted-template/scripts/host-family.py status
sudo python3 /opt/fq-hosted-template/scripts/host-family.py configure \
  --slug guest-01 --config /root/intake/guest-01/family.json
sudo python3 /opt/fq-hosted-template/scripts/host-family.py backup --all
sudo systemctl status fq-hosted-backup.timer
```

`configure` проверяет файл, создаёт резервную копию, меняет конфигурацию и перезапускает только выбранную службу. После этого заново экспортируйте пакет и пересоберите её APK. Смена времени или параметров цели влияет на расчёт истории; не меняйте порядок профилей. Каталог уже работающей базы меняется родителями в панели, не заменой стартового JSON.

Резервная копия SQLite делается через Backup API с проверкой целостности. ZIP также содержит конфигурацию и доступы этой семьи, хранится под root в закрытом каталоге. Ежедневная копия запускается в 03:15 UTC со случайной задержкой до 15 минут. Автоматического удаления архивов нет: проверяйте диск и переносите нужные копии в согласованное закрытое хранилище. Локальные архивы не защищают от потери самого VPS; внешний бэкап настраивается отдельно.

Для восстановления остановите только нужную `fq-hosted-SLUG.service`, сохраните её текущие файлы, восстановите базу из выбранного проверенного архива и права владельца, затем запустите службу и проверьте данные с родителем. Не восстанавливайте чужой архив в другую семью. Перенос данных и ротацию токенов согласуйте с владельцами этой семьи.

Сертификаты создаются Certbot через HTTP-01 на отдельное имя. Обновление обслуживает существующий таймер `certbot renew`; убедитесь, что он включён и после продления перезагружает Nginx. [Certbot webroot](https://eff-certbot.readthedocs.io/en/stable/using.html#webroot). Не отключайте проверку TLS на клиентах.

Для приостановки семьи остановите и отключите только её службу, удалите её ссылку из `sites-enabled`, проверьте `nginx -t` и перезагрузите Nginx. Сохраните файлы и пометьте `enabled: false` в её `instance.json`. Удаление данных выполняется отдельно по согласованию.
