# Обновление с сохранением семьи

Текущие исходники публичного шаблона — **1.3.5, Android versionCode 50**, ветка `main`. Частная адаптация может иметь другой номер. Сверяйте `AndroidManifest.xml` своей копии и установленный пакет. Обновление только документации не требует переустановки приложений.

## 1. Определите нужные компоненты

| Изменение | Что требуется |
| --- | --- |
| Дела, ставки супердел, повторения, задания дня и цели через кабинет | Сохранение и обмен; для личных целей и повторений нужен клиент 1.3+ |
| Имена, фотографии и исходные параметры семейной сборки | Проверка конфигурации, новый семейный пакет и пересборка APK |
| Код начислений | Согласованное обновление `sync/family.py` на сервере и `web/rules.js` в кабинете и всех APK |
| Детский интерфейс или Android-оболочка | Пересборка APK нужного режима |
| Только инструкции | Актуальная документация |

## 2. Сделайте резервную копию

Сохраните целостную SQLite-копию через Backup API / `.backup`, конфигурацию и доступы. Для сервера приглашений есть команда `backup` в [инструкции владельца](operator-hosting.md#обслуживание-и-резервные-копии).

1. Сохраните рабочую базу, активный каталог, фото и настройки.
2. Сохраните родительские доступы и токены устройств с их `.properties`.
3. Сохраните `.local/signing.p12` и `.local/signing.pass`.
4. Оставьте предыдущие рабочие файлы сервера и APK для восстановления.

Начальный `sync/catalog.json` не заменяет каталог рабочей базы. Генерация новых доступов и повторная инициализация семьи не являются обновлением.

## 3. Подготовьте исходники

Получите `main` или изменения в своём fork. Просмотрите [журнал изменений](../CHANGELOG.md) и различия с адаптацией. Сохраните семейную конфигурацию, порядок профилей и использованные ID дел. Не подменяйте их демонстрационными примерами.

При изменении кода выполните [проверки проекта](install.md#проверки-проекта). Новые условия вводите с определённой даты, отдельно проверяя прошлые начисления. Семейный APK использует свои данные и прежнюю подпись.

## 4. Обновите сервер

1. Для приглашённых семей владелец обновляет проверенный шаблон и выполняет [обновление выбранной семьи](operator-hosting.md#обновление-зарегистрированной-семьи).
2. На своём сервере после резервной копии замените изменённые файлы, сохранив данные, доступы и конфигурацию. При изменении серверного кода перезапустите службу.
3. Проверьте службу, HTTPS, вход родителей и фактические показатели. Перезагрузите кабинет для получения нового клиентского расчёта.
4. Сравните прошлые даты и копилки. Проверка не должна создавать вымышленные отметки или выдачи времени.

Пути берите из своей установки. Команды создания пользователя и доступов из [первичной установки](hosting.md) повторно не выполняются.

## 5. Обновите детские экраны

Используйте прежнюю подпись, семейные доступы и режим устройства:

```sh
bash scripts/build-android.sh .local/connection/tv.properties .local/apk/family-quest-tv.apk
# При наличии отдельно подключённой машины:
bash scripts/build-android.sh .local/connection/car.properties .local/apk/family-quest-car.apk
```

Для разрешённого ADB-подключения:

```sh
adb devices -l
adb -s SERIAL install -r .local/apk/family-quest-tv.apk
adb -s SERIAL shell dumpsys package org.familyquest.starter
```

Для машины укажите её `SERIAL` и автомобильный APK. Сверьте `versionName` и `versionCode`, откройте приложение и проверьте обмен. При другом разрешённом способе установки проверьте тот же результат. Пакет и подпись сохраняют обновление поверх; удаление приложения может потерять ещё не отправленную очередь.

## 6. Зафиксируйте результат

1. На каждом доступном экране подтверждены версия, правильная семья и обмен.
2. Пульт или касания работают; дела и цели совпадают с кабинетом.
3. В рабочем журнале не создавались вымышленные достижения ради теста.
4. Временная отладка закрыта разрешённым способом и проверена: обычная работа использует HTTPS.
5. Недоступные устройства названы явно. Готовая сборка ещё не означает установку; один обновлённый экран не обновляет остальные.

При неуспехе используйте сохранённые файлы и копию для согласованного восстановления. Возврат APK на меньший versionCode может требовать отдельных действий; не удаляйте приложение вслепую ради обхода ошибки.
