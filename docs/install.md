# Установка

**Семья с личным приглашением:** основной маршрут уже описан в [руководстве для помощника](agent-guide.md) — от регистрации до работающего телевизора. Сервер разворачивать не нужно. Команды про создание своего сервера ниже нужны только при отдельной самостоятельной установке. Пользование готовым приложением — в [памятке семьи](family-guide.md).

## 1. Локальная проверка

Нужен Python 3.9 или новее. Из корня репозитория:

```sh
python3 scripts/configure.py
python3 scripts/init-instance.py --directory .local/preview
python3 sync/server.py --preview \
  --database .local/preview/journal.sqlite3 \
  --tokens .local/preview/devices.json --parents .local/preview/parents.json
```

Откройте [панель на этом компьютере](http://127.0.0.1:8765/parent/). Введите один из новых кодов из локального `.local/preview/parents.json`. Проверьте добавление задания дня и вход второго родителя. Приложение Android для синхронизации использует HTTPS, поэтому следующий шаг нужен для обмена с устройствами.

## 2. Общий журнал и родительская панель

Если семью пригласили на сервер автора, пропустите развёртывание сервера и следуйте [подключению по приглашению](hosted.md). Зарегистрируйтесь по личной ссылке; закрытый пакет для экранов скачивается в вашем кабинете, без передачи файлов через автора. Команды ниже — для собственного сервера.

Для постоянной установки начните с [выбора VPS и пошаговой настройки systemd и HTTPS](hosting.md). Ниже — команды для ручного запуска на сервере с уже настроенным HTTPS-прокси.

Возьмите Linux-сервер и домен. Направьте DNS домена на сервер. На сервере клонируйте свою копию проекта и перенесите в неё согласованные настройки семьи. Подготовьте закрытый каталог для базы и входов. В примере замените `tracker.example.org` на свой домен, при необходимости уберите автомобиль из списка.

```sh
python3 scripts/configure.py
python3 scripts/init-instance.py --directory .local/instance \
  --origin https://tracker.example.org --device tv:tv --device car:car
python3 sync/server.py --origin https://tracker.example.org \
  --database .local/instance/journal.sqlite3 \
  --tokens .local/instance/devices.json --parents .local/instance/parents.json
```

Сервер приложения слушает `127.0.0.1:8765`. Настройте Caddy или другой HTTPS-прокси. Пример Caddyfile с сертификатом для вашего домена:

```caddyfile
tracker.example.org {
    reverse_proxy 127.0.0.1:8765
}
```

Для постоянной работы перенесите команду Python в службу systemd под отдельным пользователем. Задайте абсолютный рабочий каталог, право записи только в каталог данных и автоматический перезапуск. Для резервной копии активной базы используйте команду SQLite `.backup`. Храните копию вне каталога веб-приложения.

Оба родителя открывают `https://tracker.example.org/parent/`, вводят каждый свой код из `parents.json` и при желании добавляют панель на главный экран из меню браузера. Android получает свой отдельный токен. Для одного дома и машины достаточно одного журнала.

## 3. Сборка детского приложения

На компьютере сборки понадобятся JDK 17, Android SDK Platform 35 и Build Tools 35.0.0. Укажите `JAVA_HOME` и `ANDROID_HOME` или `ANDROID_SDK_ROOT`. Пакет рассчитан на Android 9 и новее. Собирайте из той же версии репозитория с тем же `config/family.json`, что на сервере.

```sh
# Только локальный журнал для проверки экрана
bash scripts/build-android.sh

# Индивидуальная сборка со связью с журналом
bash scripts/build-android.sh .local/instance/tv.properties .local/apk/family-quest-tv.apk
bash scripts/build-android.sh .local/instance/car.properties .local/apk/family-quest-car.apk
```

Передайте файлы `.properties` с сервера на компьютер сборки по закрытому каналу. APK со связью содержит токен устройства. Доступ можно отозвать, удалив токен из `devices.json` и перезапустив сервер. Для обновлений сохраняйте ключ подписи из `.local` и поднимайте `versionCode` в манифесте. Раздавайте отдельные сборки частным способом.

Для пробного APK используйте вымышленные отметки. Семейный журнал начните после подключения первой сборки с HTTPS-настройками.

## 4. Подключение экрана

Сверьте [режим устройства и список проверок интерфейса](screens.md) перед сборкой.

- **Android TV и Google TV.** На телевизоре откройте настройки сети и подключите к тому же Wi-Fi, что и компьютер. Если устройство предлагает беспроводную отладку, включите её и выполните `adb pair HOST:PAIR_PORT`, затем `adb connect HOST:DEBUG_PORT`, используя адреса и порты с телевизора. Для старых моделей смотрите инструкции производителя. Подключение и код подтверждает владелец.
- **Android-планшет.** Можно установить APK штатным способом с разрешением установки из выбранного источника или через ADB. На Android-устройстве с нужной настройкой доступен режим касания.
- **Android в машине.** Работайте только на стоянке. Проверьте модель головного устройства и штатную поддержку установки сторонних APK. Для установки используйте разрешённый производителем способ. Для обмена с журналом нужен интернет через Wi-Fi или LTE. Если система закрыта, используйте Android-планшет. Android Auto и CarPlay сами по себе не заменяют отдельное Android-устройство.

При доступной и авторизованной отладке выполните `adb devices -l`, убедитесь, что выбрали нужный экран, и установите поверх `adb -s SERIAL install -r ПУТЬ_К_APK`. Не открывайте ADB в интернет. Откройте приложение, проверьте пульт или касание и попробуйте в родительской панели добавить «Полить цветы». Отметьте дело на экране и убедитесь, что отметка появилась у родителей. На втором экране проверьте ту же отметку по Wi-Fi, а при необходимости через LTE.

Для отдельного планшета при первичной настройке добавьте `--device tablet:touch` к команде `init-instance.py` и соберите APK с `tablet.properties`. Для дополнительного устройства в уже действующем журнале добавьте ему отдельный новый секрет в `devices.json` и создайте его `.properties` по тому же образцу. Затем перезапустите сервер и соберите APK.

[Документация Android по ADB](https://developer.android.com/tools/adb) · [Caddy reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)

## Проверки проекта

```sh
python3 scripts/configure.py --check
# Для тестов регистрации нужен Pillow (Ubuntu: sudo apt install python3-pil).
python3 -m unittest discover -s tests
npm install --no-save playwright
npx playwright install chromium
node --test tests/*.cjs
```

Для проверки с установленным Chrome можно задать `FAMILY_TEST_CHROME` с путём к исполняемому файлу.
